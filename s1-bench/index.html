02 / RELIABILITY

Two tests. One reliability score.

Reliable decisions stay consistent when options move—and recognize when no answer is correct.

S

ORDER STABILITY

Same answer, different order.

Shuffle the options and measure how often the model keeps its original answer, tracking the answer’s identity rather than its position.

S = (A − pₑ) / (1 − pₑ)

A is mean agreement across 939 items × 12 shuffles.
pₑ = mean(1/Kᵢ) is chance agreement, where Kᵢ is the number of options.

0 Chance agreement1 Fully stable

Consistency does not necessarily mean correctness.

N

NULL DISCRIMINATION

Know when no answer fits.

Compare each original question with a version that removes its sole correct answer. The model should assign higher null probability to the latter.

N = 2 × AUC − 1

AUC separates answer-removed from answer-present requests using pnull = 1 − p(yes).
597 paired items → 1,194 requests, pooled across all items.

0 Chance separation1 Perfect separation

AUC compares all positive–negative pairs; ties receive half credit.

COMBINED RELIABILITY

Both dimensions have to work.

The geometric mean penalizes weakness in either dimension.

100R = 100 × √(S × N)

When S > 0 and N > 0; otherwise 0.

PUBLIC INPUT → MODEL
No answer leakage
The model sees the goal, current observation, public history, and candidate options. Reference answers and checker internals stay outside its input.
MODEL → EXECUTOR
Choose, then execute
The model selects a typed action. Deterministic code executes it in the source simulator. No auxiliary model fills in the action.
EXECUTOR → CHECKER
Outcome, not exact wording
Native task checkers evaluate the required state and constraints. Valid alternative tool routes can succeed.
Missing information is feedback.
A missing grounded required argument is reported to the model. The executor does not invent a value or run that invalid call. The attempt still consumes the applicable budget.
Tool sandbox ≠ Web replay.
Tool episodes run live in BFCL and ToolSandbox simulators. Medium and hard Web tasks follow replay-verified reference routes; progress stops at the first wrong decision, with accepted alternatives and harmless detours handled by the checker.
Bounded, auditable execution.
Decision and tool-call budgets bound each episode. Execution records preserve actions, feedback, and native outcomes. Controlled completion-verification tasks separately test whether a model checks the history—not just the final state.

Task credit rules: what does cᵢ mean?
Choice & binary
Correctness of the top-probability outcome: 0 or 1.
Label sets
Per-item Jaccard: |predicted ∩ reference| / |predicted ∪ reference|.
Ordinal ratings
Adjacent-grade credit: max(0, 1 − |ĝ − g| / 2), using the hard predicted grade.
Tool episodes
The task’s native outcome score from its execution checker.
Web routes
Fraction of scored decisions completed correctly before the first error.
Refusals & context limits
Explicit refusals and over-window inputs receive zero under the paper’s stated policy. Inputs are not truncated.
